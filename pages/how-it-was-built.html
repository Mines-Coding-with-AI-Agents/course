How this course was built

A note from {{ instructor }}, who teaches the course. September 2026.

I built this course with Claude Code, the same coding agent my students first learn to use and then learn to engineer.

The lesson plans, quizzes, slides, lab checkers, and the repository my students work in all come out of one Git repository that I started on June 20, 2026, and by late September it held more than 200 commits. This page explains how that works, what the agents did, and where I stayed in charge, because a course about working with agents should be able to show its own working.

The course lives in three kinds of repository.

  • A private workspace for the instructor. It holds the lesson plans, the answer keys, and a log of every design decision with the reason behind it.
  • A private course repository for students. Enrolled students clone it once and update it before every class. It is written for them and for their agent, so a good way in is to open Claude Code inside it and ask what to do next.
  • Public project repositories that students own. All four projects ship as public GitHub repositories, so the work stays with the student after the semester ends.

Six skills do the repeatable work.

A Claude Code skill is a written procedure that the agent loads when a task calls for it. Six of them build this course:

develop-lecture
turns a calendar entry into a full lesson plan and the lecture's page on Canvas.
generate-quiz
writes the short in-class quiz and packages it so that Canvas can import it directly.
generate-slides
builds the deck, with one full-sentence headline and one visual per slide and the talk track in the speaker notes.
author-student-materials
writes the pre-class preparation, the lab with its checker script, and a step-by-step replay of the in-class demo.
release-materials
copies a finished lecture into the student repository at least a week before class and tags the release.
develop-student-feature
builds and tests the tools that students use inside their repository.

Each skill is a living document. When I say I want something done differently, the change goes into the skill, so every later lecture follows it without my having to repeat myself.

Research comes before writing.

Before I wrote a lecture, seven research agents surveyed the public course listings of about 150 US universities to see what was already being taught about coding agents. What they found, as of June 2026, shaped where the course puts its weight: writing an agent from the raw model API and then porting it to a production SDK, building an MCP server, measuring retrieval with real information-retrieval metrics, treating evaluation as an experiment, and a full unit on agent security. Nine more agents then critiqued the whole design: six read it as students with different backgrounds, and three read it for how current it was, how deep it went, and what employers look for. In late July, a twelve-agent pass checked every lecture plan against the newest models and tools before the semester began.

The same habit continues during the semester. When I judged the first plan for lecture 7 too basic for students who had already built and steered an agent loop, a research pass through about 150 primary sources rebuilt it around five rules for debugging agent output. Lectures 8 to 11 were rebuilt the same way.

The agent writes, and something else checks.

Nothing an agent writes reaches my students on the agent's word. Each lecture goes through separate reviewer agents that check its accuracy, its consistency with the rest of the course, and whether the lab actually runs, and then I read it myself. It is the rule my students learn in lecture 7: the one who does the work is not the one who judges it.

My own corrections go into the skills. When the slides came out too full, the rule became one full-sentence headline and one visual per slide. When the student pages read as clipped and cold, I asked for the voice of a teaching assistant in office hours, and every page was rewritten. When an explanation squeezed a lab result into a four-word slogan, the rule became to say what was tried, give the numbers before and after, and say what the difference means.

Students work inside a repository built for their agent.

My students do not just read the course repository; they work in it with Claude Code. A handful of commands carry most of the semester:

/prep
walks a student through the pre-class video or reading and answers questions about it.
/quiz-me
checks that the student is ready for the in-class quiz.
/lab start 07
copies the lab's starter code into the student's own space, and /lab check 07 runs the lab's checker and names what is still missing without fixing it.
/demo 07
replays the in-class demo one step at a time, with the student typing the prompts.
./bin/update
pulls the week's new material without ever losing a student's own edits.

A hook stops the agent from writing anywhere except the student's own work folder, so the course files stay intact whatever a student asks for, and a progress file that the agent keeps on the student's word shows what is still open before the next class.

Some things stay private.

Answer keys, my lesson plans with their facilitation notes, and grading details stay in the private workspace. No student's work appears on this site unless that student chooses to share it.
