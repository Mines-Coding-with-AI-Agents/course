Students build the machinery behind coding agents, not just use it.

  • An agent written from scratch

    Students write a working agent loop directly against the model API, then port it to the Claude Agent SDK.

    Lectures 20 and 21

  • Tools and an MCP server of their own

    They redesign a tool one change at a time, measure its reliability over repeated runs, and build a Model Context Protocol server.

    Lectures 10 and 16

  • Retrieval measured properly

    Their retrieval systems are scored against a gold set with recall@k, MRR, nDCG, and faithfulness, the way search engineers measure retrieval.

    Lectures 12 to 14

  • Evaluation run as an experiment

    They read benchmarks for contamination, report pass@k with error bars, and check where a model grader is biased.

    Lectures 22 to 24

  • Debugging that does not take the agent's word

    They start from a failing test, rank their hypotheses, and accept a fix only with evidence, because the agent that wrote the code does not get to judge it.

    Lecture 7

  • Attacks on their own systems

    They run prompt injection against their own retrieval pipelines, then add guardrails and human approval gates.

    Lecture 26

The course is built with the same tools it teaches.

Its lesson plans, quizzes, slides, and lab checkers come out of a Git repository in which Claude Code drafts the work under six reusable skills, separate reviewer agents check each draft, and the instructor has the final say. Since the first commit on June 20, 2026, that repository has grown past 200 commits.

Students work the same way. The course repository they clone is written for them and for their agent, so they open Claude Code inside it to prepare for class, to start and check their labs, and to replay the in-class demos one step at a time.
